# ZenCode

ZenCode 现在使用本地浏览器工作台。Java 进程负责 Agent、工具、权限和会话；浏览器不接收已保存的 Provider API Key，新输入的密钥仅发送给本机服务保存，不写入浏览器持久存储。

## 启动

1. 在 Windows 中运行 `start-zencode.cmd`。脚本会离线打包当前代码（不运行测试），然后启动 Java 服务并尝试打开浏览器。
2. 没有 `config.local.yaml`、文件为空或配置未通过校验时，会进入仅配置模式。填写模型配置并点击“保存并应用”，同一页面即可开始聊天，不需要重新打开终端。也可继续参考 `config.example.yaml` 手动填写私有配置。
3. 如果浏览器没有自动打开，访问启动窗口打印的 `http://127.0.0.1:<端口>` 地址。服务只监听本机回环地址，关闭启动进程会停止服务。不要把 API Key 提交到仓库。

已经打包过时，也可以直接运行 `zencode.cmd --config config.local.yaml`。Maven 离线缓存缺失时，重新打包可能失败；此时旧 JAR 不代表最新源码。

## 模型设置

顶部“模型设置”可编辑已有 Provider 或新增 Provider，并设置默认项。修改的是本次启动实际使用的 `--config` 文件；未传参数时使用用户目录下的 `.zencode/config.yaml`。页面会显示保存位置、当前运行模型及下次启动的 Provider。

- OpenAI 兼容协议使用 Chat Completions：Base URL 填 API 根地址，例如 `https://your-provider.example/v1`，程序追加 `/chat/completions`，不要填写完整请求地址。
- Anthropic 协议：例如填写 `https://your-provider.example`，程序追加 `/v1/messages`，末尾不要重复填写 `/v1`。具体模型 ID 以服务商提供的值为准。
- API Key 留空会保留已有值；新建 Provider、更改地址或更改协议时需重新填写，避免密钥被复用到其他服务。可以直接输入密钥，也可以输入 `${ENV_NAME}`，该环境变量须在启动进程中已设置。思考开关仅对当前 Anthropic 实现生效。
- 直接填写的密钥以明文写入本地 YAML，文件会限制为当前文件所有者可访问。页面不回显已保存密钥，不存入 localStorage；保存成功或关闭弹窗会清空密钥输入框，保存失败则保留当前输入便于修正。仓库内的目标配置必须已被 Git 忽略且未被跟踪，示例配置禁止保存密钥。
- “保存并应用”只做本地格式校验、保存及模型客户端切换，不发送验证请求；“已应用”不表示密钥或服务连通性已经验证。切换保留当前会话，并同步主 Agent、摘要、记忆和后续子 Agent 的配置。
- 聊天、后台任务或模型请求尚未完全结束时会拒绝保存与切换。已创建的团队队员（包括空闲队员）必须先停止，避免外部队员继续使用旧凭据。停止按钮返回后，底层任务可能仍需短暂收尾。
- 热切换限当前 Java 进程及其进程内子 Agent，不会向外部 tmux/iTerm2 进程传播凭据。当前外部后端无法可靠确认退出；本次工作台若启动过外部队员，即使界面标记已停止，也须手动关闭其进程并重启工作台后再更改模型。外部队员的独立配置继承不在此功能范围内。
- 当前页面选择的 Provider 立即生效；“默认启动”与启动参数 `--provider` 决定下一次启动使用哪一项，后者优先。环境变量引用只能读取当前 Java 进程已继承的变量；新设置的系统环境变量仍需要重启进程，直接填写密钥则不需要。
- 保存保留其他 Provider、非模型配置和 YAML 注释，但可能调整排版。文件被外部修改会拒绝覆盖，需重新加载；无法解析的 YAML 或集合别名配置需先手动修复。非模型设置仍在下次启动时加载。仅配置模式在应用前不会初始化 Agent、MCP 或启动钩子；首次应用会进行正常工作台初始化。
- 保存结果不确定（例如浏览器请求超时）时，先点击“重新加载”确认，避免重复提交。若提示“已保存但未应用”，当前运行模型不变，修正本地初始化问题后再次应用。

## 模型请求错误

错误提示会区分 HTTP 认证/权限/路径/限流/服务异常，以及 DNS、TLS、连接失败、超时和流读取异常；不会输出原始响应正文、异常消息或密钥。`IOException` 不能直接等同于密钥无效。新连接最多等待 30 秒；这不是整段流式响应的总时长限制。

## 工作台

- 中间是对话和流式回复，右侧可切换工具调用的安全摘要与当前 Git 文件变更。
- 助手回复支持 Markdown 标题、列表、表格、引用和链接；代码块显示语言、高亮与复制按钮，未知语言按纯文本展示。思考过程默认折叠，可点击展开。
- Markdown 与高亮资源随 JAR 离线打包；消息中的 HTML 按文本显示，图片只显示说明，不自动加载外部资源。
- 流式输出在底部自动跟随；向上翻阅或选中文本会暂停跟随，点击“回到最新”或向下滚回底部可恢复。选中正在生成的正文时会暂缓重新排版，取消选择后补齐内容。
- 提交期间、运行中和停止中会拦截重复发送；可以继续编辑下一条草稿。提交失败保留输入，成功也不会清空等待期间新编辑的内容。
- 页面刷新或断线重连时，从 Java 进程获取完整消息快照，同时恢复运行状态、工具摘要和仍有效的待审批请求；长回复不再受最近 3000 条增量事件的限制。事件缺失时自动重新同步，网络恢复不会自动重发任务或审批。
- 连接中断会自动重试，也可点击“立即重连”。恢复期间保留当前页面和输入内容；此处恢复针对仍在运行的 Java 进程，不会自动重新启动已退出的服务。重新启动后可从最近对话恢复已存档内容。
- 窗口较窄时，顶部“执行记录”打开右侧面板；小窗口顶部“会话”可新建或恢复对话。面板支持关闭按钮、Esc 和点击遮罩关闭，放大窗口会恢复两侧布局。
- “文件变更”支持路径筛选，点击文件可查看带原/新行号、增删标记的逐行差异，切换“工作区”（相对暂存区）和“暂存区”（相对 HEAD）；也可预览未跟踪的 UTF-8 文本、折行和复制相对路径。任务结束或重连后，已打开的变更视图会刷新，也可手动刷新。
- 变更查看仅针对当前工作目录内的 Git 未提交变更，不代表本次 Agent 独有的修改；不提供暂存、回滚等写操作。列表最多 200 个文件，单文件预览最多 256 KiB / 4000 行；二进制、非 UTF-8 新文件、链接、子模块、冲突和超限内容会明确提示，不跟随链接读取工作区外文件。
- 写入、命令等需要确认的操作会显示权限弹窗；可在顶部切换权限模式。
- 左侧可新建或恢复已保存的会话。斜杠命令仍可在输入框中使用。
- 浏览器关闭不会自动结束后台 Java 进程；在启动窗口按 `Ctrl+C` 退出。

浏览器工作台不依赖真实模型来显示页面，但发送任务仍需要有效的 Provider 配置。本地前端与 Java 进程之间使用随机会话令牌，页面不会连接外网资源。
