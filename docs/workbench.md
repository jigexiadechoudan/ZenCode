# 工作台指南

ZenCode 现在使用本地浏览器工作台。Java 进程负责 Agent、工具、权限和会话。Provider API Key 仅在本次 Java 进程内存中使用，不写入本地配置或浏览器持久存储，也不从服务器回显。每次重新运行脚本都需要重新填写密钥。

## 启动

1. 在 Windows 中运行 `start-zencode.cmd`。脚本会打包当前代码（不运行测试），然后启动 Java 服务并尝试打开浏览器。
2. 每次启动都会进入仅配置模式。模型地址、模型 ID 和默认项会保留；重新填写本次运行使用的密钥，点击“保存并应用”后即可开始聊天。启动时会清除旧版配置中遗留的 Provider `api_key` 字段；无法安全清理时会停止启动。
3. 如果浏览器没有自动打开，访问启动窗口打印的 `http://127.0.0.1:<端口>` 地址。服务只监听本机回环地址，关闭启动进程会停止服务。不要把 API Key 提交到仓库。

已经打包过时，也可以直接运行 `zencode.cmd --config config.local.yaml`。首次构建需联网下载依赖；打包失败时请检查 Maven 输出，旧 JAR 不代表最新源码。

## 模型设置

输入框下方的模型按钮可打开设置，编辑已有 Provider 或新增 Provider，并设置默认项。修改的是本次启动实际使用的 `--config` 文件；未传参数时使用用户目录下的 `.zencode/config.yaml`。页面会显示保存位置、当前运行模型及下次启动的 Provider。

- OpenAI 兼容协议使用 Chat Completions：Base URL 填 API 根地址，例如 `https://your-provider.example/v1`，程序追加 `/chat/completions`，不要填写完整请求地址。
- Anthropic 协议：例如填写 `https://your-provider.example`，程序追加 `/v1/messages`，末尾不要重复填写 `/v1`。具体模型 ID 以服务商提供的值为准。
- 每次进程启动后都必须填写 API Key。同一进程内，留空可沿用该 Provider 本次已输入的密钥；新建 Provider、更改地址或更改协议时需重新填写。也可手动输入 `${ENV_NAME}`，引用仅在本次运行中解析，不写入配置。思考开关仅对当前 Anthropic 实现生效。
- 密钥不写入 YAML、临时配置文件或 localStorage；“显示”仅切换当前输入内容的可见性。保存成功、关闭设置、页面离开或服务断线时会清空密钥输入框，保存失败则保留当前输入便于修正。模型配置文件仍限制为当前文件所有者可访问，仓库内的目标配置必须已被 Git 忽略且未被跟踪。
- “保存并应用”只做本地格式校验、保存及模型客户端切换，不发送验证请求；“已应用”不表示密钥或服务连通性已经验证。切换保留当前会话，并同步主 Agent、摘要、记忆和后续子 Agent 的配置。
- 聊天、后台任务或模型请求尚未完全结束时会拒绝保存与切换。已创建的团队队员（包括空闲队员）必须先停止，避免外部队员继续使用旧凭据。停止按钮返回后，底层任务可能仍需短暂收尾。
- 团队队员使用 INPROCESS 后端，AUTO 也选择 INPROCESS，继承当前进程的密钥；不向外部 tmux/iTerm2 进程传递或落盘凭据，因此不支持这些外部后端和独立队员进程启动。
- 当前页面选择的 Provider 立即生效；“默认启动”与启动参数 `--provider` 决定下一次启动使用哪一项，后者优先。环境变量引用只能读取当前 Java 进程已继承的变量；新设置的系统环境变量仍需要重启进程，直接填写密钥则不需要。
- 保存保留其他 Provider、非模型配置和 YAML 注释，但移除所有 Provider 的 `api_key` 字段，且可能调整排版。文件被外部修改会拒绝覆盖，需重新加载；无法解析的 YAML 或集合别名配置需先手动修复。非模型设置仍在下次启动时加载。仅配置模式在应用前不会初始化 Agent、MCP 或启动钩子；首次应用会进行正常工作台初始化。
- 保存结果不确定（例如浏览器请求超时）时，先点击“重新加载”确认，避免重复提交。若提示“已保存但未应用”，当前运行模型不变，修正本地初始化问题后再次应用。

## 模型请求错误

错误提示会区分 HTTP 认证/权限/路径/限流/服务异常，以及 DNS、TLS、连接失败、超时和流读取异常；不会输出原始响应正文、异常消息或密钥。`IOException` 不能直接等同于密钥无效。新连接最多等待 30 秒；这不是整段流式响应的总时长限制。

## 工作台

- 界面采用黑白灰的浅色工作站布局。左侧是普通聊天和项目，中央是对话；“轨迹与变更”按需打开右侧轨迹记录和文件变更面板。
- 助手回复支持 Markdown 标题、列表、表格、引用和链接；代码块显示语言、高亮与复制按钮，未知语言按纯文本展示。思考过程默认折叠并淡化显示，点击展开；正文使用正常字号。
- Markdown 与高亮资源随 JAR 离线打包；消息中的 HTML 按文本显示，图片只显示说明，不自动加载外部资源。
- 流式输出在底部自动跟随；向上翻阅或选中文本会暂停跟随，点击“回到最新”或向下滚回底部可恢复。选中正在生成的正文时会暂缓重新排版，取消选择后补齐内容。
- 提交期间、运行中和停止中会拦截重复发送；可以继续编辑下一条草稿。提交失败保留输入，成功也不会清空等待期间新编辑的内容。
- 页面刷新或断线重连时，从 Java 进程获取完整消息快照，同时恢复运行状态、执行轨迹和仍有效的待审批请求；长回复不再受最近 3000 条增量事件的限制。事件缺失时自动重新同步，网络恢复不会自动重发任务或审批。
- 连接中断会自动重试，也可点击“立即重连”。恢复期间保留当前页面和输入内容；此处恢复针对仍在运行的 Java 进程，不会自动重新启动已退出的服务。重新启动后可从最近对话恢复已存档内容。
- 窗口较窄时，顶部“执行记录”打开轨迹面板；小窗口顶部“会话”打开聊天与项目导航。面板支持关闭按钮、Esc 和点击遮罩关闭。
- “轨迹记录”按任务分组，展示模型阶段、工具调用、审批、轮次和结束状态，支持筛选和展开安全输入/结果摘要。当前进程内保留步骤耗时；恢复存档时从历史还原工具状态，不虚构旧任务耗时或展开原始工具输出。
- “文件变更”支持路径筛选、原/新行号、折行和复制路径；新增内容显示绿色，删除内容显示红色。Git 目录可切换“工作区”（相对暂存区）和“暂存区”（相对 HEAD），并预览未跟踪 UTF-8 文本。任务结束或重连后，已打开的变更视图会刷新，也可手动刷新。
- 普通文件夹以本次进程首次打开该目录时的内存快照为基准，显示之后的新增、修改与删除；首次打开前的修改无法还原。快照不写入磁盘，最多缓存最近 4 个目录，超出缓存后重新进入会重建基准，重启也会重建。单次扫描最多 5000 个文件 / 3 秒，原始内容总量每目录最多 16 MiB；跳过 `.zencode`、`.git`、依赖、构建与缓存目录，扫描不完整会提示且不把未扫描到的文件判为新增或删除。
- 变更包括当前目录内其他来源的修改，不代表本次 Agent 独有的修改；不提供暂存、回滚等写操作。列表最多 200 个文件，单文件预览最多 256 KiB / 4000 行；二进制、非 UTF-8、链接、子模块、冲突、超限或缺少原始内容的文件会明确提示，不跟随链接读取工作区外文件。
- 写入、命令等需要确认的操作会显示权限弹窗；可在输入框下方切换权限模式。
- 左侧可新建或恢复已保存的会话。输入 `/` 会打开斜杠命令面板，支持上下选择、Tab 补全、Enter 执行和 Esc 关闭。
- 关闭设置或浏览器页面会清空页面输入；浏览器关闭不会自动结束后台 Java 进程。关闭启动窗口或按 `Ctrl+C` 退出后，进程内的密钥缓存清除，并再次清理配置中可能被外部写入的 Provider 密钥。下次启动需重新填写。

浏览器工作台不依赖真实模型来显示页面，但发送任务仍需要有效的 Provider 配置。本地前端与 Java 进程之间使用随机会话令牌，页面不会连接外网资源。

## 普通聊天与项目

- “新建聊天”创建普通聊天，保留 Agent 与工具能力，默认工作目录是启动目录。“添加项目”在运行 Java 服务的电脑上打开文件夹选择器；支持 Git 仓库和普通文件夹，不提供手动路径输入。同一真实目录只登记一次，取消选择不会创建项目。
- 项目可展开查看聊天，通过项目下的“新建聊天”使用该项目目录。项目支持重命名和移除；移除项目会将聊天转入普通聊天，不删除项目源文件或聊天历史。
- 聊天菜单支持重命名、移动和删除。手动名称不会被后续回复覆盖；移动聊天保留消息历史，后续工具操作使用目标项目目录，移出项目则恢复默认目录。项目目录丢失或位置改变时拒绝执行，不自动回退到其他目录。
- 所有聊天统一保存在启动目录的 `.zencode/sessions/`，项目清单保存在 `.zencode/projects.json`。按仓库脚本启动时，存档仍在 `<启动目录>/.zencode/sessions/`，不会写入选中的项目会话目录。旧会话自动归入普通聊天，不搬迁或重写原始消息。关闭记忆功能也不会关闭会话存档。
- 当前只运行一个活动聊天。切换前保存历史并重建目标目录的工具、规则、技能和 Git 视图；模型客户端和本次密钥由进程共享，不需重复输入。切换不会发起模型请求或重复执行启动钩子；初始化失败时保留原聊天。
- 聊天、模型流、记忆提取、后台任务或队员尚未完全结束时不能切换、移动或删除；停止之后需等待实际收尾。输入草稿按聊天分别保留在当前页面内，刷新或关闭页面后不持久保存。
